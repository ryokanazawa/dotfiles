# PR作業規約

PRの作成・レビュー・修正・マージ時に適用する。

## 権限

- 明示的なマージ依頼（`land`）は必要なブランチ変更とpushを許可する。自分のdraft PRなら、必要に応じてreadyにして進める。
- `rewrite commits + land` はコミット列の整理、合意済み範囲の検証、force-push、マージを含む。PR本文の検証記述の磨き込みやCIの継続監視は依頼時だけ行う。

## 修正と品質

- 既存PRを修正・書き直してマージすることを優先する。PRを閉じて同じ変更を直接コミットし直す方法は避ける。
- 生成コードも品質を前提にせず、マージ前にレビューして改善する。明快になるなら全面的な書き直しもよい。
- PR作業中に見つかった、確度の高い不安定なテストの修正や、範囲を限定した近傍のリファクタ・整理は含める。変更の一貫性を保ち、挙動を検証する。
- UI変更のPRには変更前後の画像を含める。秘密・個人情報・非公開データ・内部限定の識別子などを事前に除く。安全に撮影・加工できなければ阻害要因を報告し、アップロードしない。

## 変更履歴と貢献者

- 利用者向けの修正・マージにはchangelogを付ける。テストのみ・内部変更のみなら不要。
- 外部貢献者にはchangelogの編集を求めず、メンテナーまたはAIがマージ時に追記し、`@login` に謝意を示す。
- PRコミットの作者から `Co-authored-by: Name <email>` をコミット本文へ引き継ぎ、貢献者のクレジットを残す。利用者向け変更はchangelogでも `@login` に謝意を示す。

## 完了

- マージ後は `main` をチェックアウトし、`git pull --ff-only` と `git status -sb` で同期を確認してから報告する。
