# コミット

今セッションの変更を論理単位でコミットし、mainへ反映してpush・同期確認まで完了する。単純な「commitして」もこの範囲を許可する。明示的なローカル完結の依頼では、現在のチェックアウトでコミットして終了する。

## 守る条件

- 対象変更だけを名指しでステージする。同じファイルに無関係な変更があれば対象ハンクだけを含める。`git add -A`・`git add .` は使わない。秘密や認証情報を含めない。
- 新しいブランチを作らず、amend・force-push・検証や署名の迂回（`--no-verify`・`--no-gpg-sign`）を行わない。
- タイトル・本文は日本語。issue参照になる `#N` は使わず、必要なら「todo 147」のように書く。
- 各コミット末尾に `Co-authored-by: NAME <EMAIL>` を付ける。実行中モデルの正確な名前と、環境の指示・設定で確認できるエージェント用メールを使う。Cursorでは `cursoragent@cursor.com`。他モデルの表記の流用や値の捏造、プレースホルダは不可。不明なら確認する。本文とtrailerの前には空行を置く。

## 1. 対象を確認する

`git status`（`-uall` は不要）、`git diff`、`git diff --staged`、`git log --oneline -10` を独立に確認する。未追跡ファイルも対象分を読む。今セッション由来の変更、無関係な変更、秘密の候補を区別し、コミットの単位を決める。対象がなければその旨を報告して終了する。

## 2. 変更履歴を整える

既存の `CHANGELOG.md` または同等のファイルへ、機能・挙動・UI・公開API/CLIの変更、利用者が観測できる修正や移行を簡潔な1行で追記する。利用者に影響する文書変更も含む。

テスト・内部リファクタ・CI・型・コメントのみ、利用者影響のない文書や依存更新、取り消した変更は追記しない。changelog相当が存在しなければ新設せずスキップする。

既存の未リリース欄、分類、順序、文体に合わせ、同旨の項目は重複させない。書式は既存例から判断する。未リリース欄がなければ既存形式に合わせ、次のpatch番号を確定できる場合だけ版番号付きの欄を作る。必要な版番号を確定できない場合は確認する。PR番号は既存の慣習がある場合だけ記す。

App Store向けのリリースノートは提出準備・明示依頼時だけ更新する。リリースを実施した作業では、検証済みの版の次のpatchを `Unreleased` として用意する。

## 3. 最終差分をレビューする

`autoreview` スキルに従い、changelogを含む対象差分をレビューする。除外パスと実行済みの検証を伝える。範囲内の阻害事項を修正し、挙動や変更履歴も修正結果に合わせる。受け入れるべき指摘が残る場合はコミット・pushへ進まず、残件と理由を報告する。

## 4. コミットする

論理単位ごとに対象をステージし、ステージ差分がレビュー済みの内容と一致することを確認してコミットする。実装とその変更履歴は同じ単位に含める。無関係なステージ済み変更が混在していれば、そのままコミットせず対象だけを安全にコミットできる状態にする。他人の変更は保持する。

hookが失敗したら、範囲内の原因を直して関連検証・autoreviewを更新し、再ステージして再度コミットする。SHAとタイトルを記録する。ローカル完結の依頼ならここで報告する。

## 5. mainへ反映して同期する

現在地がmainでなければ [worktree統合](references/worktree統合.md) に従い、detached HEADも含めてmainへfast-forwardで統合する。作業側からpushして終えない。

mainのチェックアウトから `git push` する。upstream未設定なら `git push -u origin main`。続いて `git pull --ff-only` と `git status --short --branch` で同期を確認する。

pushが失敗したらforceせず原因を確認する。追加のpull・rebaseが必要なら確認を求める。未コミット変更の退避が必要な場合だけ [未コミット変更の退避](references/未コミット変更の退避.md) を読む。

## 完了と報告

対象だけがレビュー済みの日本語コミットになり、mainに反映され、リモートと同期したら完了。ローカル完結の依頼では現在地でのコミットまでを完了条件とする。

SHAとタイトル、changelogの変更またはスキップ理由、main反映・push・同期の結果を簡潔に報告する。除外した変更、復元できていないstash、未完了の操作があれば明記する。
