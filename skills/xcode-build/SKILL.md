# xcode-build — ビルドしてシミュレータで起動する

`scripts/build-run.sh`（このスキルの基準ディレクトリ配下）が、コンテナ判定・ビルド・インストール・起動までを1コマンドでやる。エージェントはスキームを決めて渡し、出力を報告するだけ。

- **Xcode.app は起動しない。** ユーザーの作業中ウィンドウを奪うため。Simulator.app は成果物なので起動する。
- **read-only。** ソースには触らない。エラーは原文で報告して止まる。修正は別の依頼。

## 手順

1. リポジトリの `CLAUDE.md` / `AGENTS.md` / `README.md` にビルド規約がないか確認し、**あればそれを最優先でスキームを選ぶ**。無ければスキーム名を省略してよい（1つだけなら自動、複数なら候補を出して停止する）。今変更した内容に合う軸を選ぶこと（言語別・Watch 別などのスキームがある場合）。

2. 実行する。ログ全文は `/tmp/xcodebuild.log` に残る。

```sh
# 先頭は展開時に提示される「Base directory for this skill」の値
/Users/ryo/.claude/skills/xcode-build/scripts/build-run.sh "スキーム名"
```

3. 報告する。
   - 成功: スクリプトの出力（container / scheme / 警告数 / シミュレータ / 起動 pid）をそのまま伝える
   - 失敗: 出力された `error:` 行を原文のまま（`ファイル:行:列` とメッセージ）。要約に丸めない
   - **警告 0 件でも「解消された」と書かない。** インクリメンタルビルドで再コンパイルされなかっただけのことが多い。`loglines` が小さければキャッシュヒットなので、その旨を添える

## シミュレータのログを見る

起動時の stdout/stderr は自動でファイルに落ち、パスが `applog:` 行に出る。os_log と合わせて読むには：

```sh
/Users/ryo/.claude/skills/xcode-build/scripts/build-run.sh --logs [行数]
```

既定はアプリ自身の `Logger(subsystem:category:)` 出力だけに絞る（素通しすると WebKit / Security の雑音が数百行来る）。システムログまで要るときだけ `--logs all`。**ユーザーにターミナルでのコピペを求めない。**

## 失敗したら

`scripts/build-run.sh` 冒頭のコメントに症状別の対処が書いてある。まずそれを読む。スクリプトを迂回して `xcodebuild` を手打ちしない（env 汚染対策がスクリプト側に入っているため）。

## 完了条件

- スクリプトが終了コード 0 を返している。シミュレータ／macOS 経路なら起動まで、候補が無い構成なら `note:` 行つきでビルドのみ完了している。または、失敗内容がエラー原文つきで報告されている。
- ソースは手つかずである。
- Xcode.app を起動していない。
