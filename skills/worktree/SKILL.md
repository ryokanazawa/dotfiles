# worktree

機能に関連した短い名前でworktreeを作る。タスク内容が分かった時点でブランチを命名し、実装開始やIDEで開く前に済ませる。内容が不明なら仮名で開始し、内容が固まった時点で改名する。特定のエージェント名、専用ツール、保存先を前提にしない。

## 命名

- 機能や修正内容を表すkebab-case、1〜3語、64字以内。例: `fix-login`、`csv-export`、`dark-mode`。
- チケット番号・日付・モデル名は含めない。不明な段階では `wip` などの仮名を使い、衝突時は短い接尾辞を付ける。
- 自分で管理するworktreeのディレクトリ末尾とブランチ名全体を同じ名前にする。例: ディレクトリ `csv-export`、ブランチ `csv-export`。`claude/`、`codex/` など、作成者・エージェント・ツール名の接頭辞は付けない。
- 作成・改名前に移動先の存在、`git branch --list`、`git worktree list --porcelain` で衝突を確認する。既存の名前を強制上書きしない。

## 作成

1. `git status -sb` と `git worktree list --porcelain` で現在地と既存worktreeを確認する。すでにこのタスク用のworktree内ならそれを使い、命名のために追加作成しない。
2. 環境のworktree管理機能が利用できる場合は、公開されているツール仕様に従って作成・選択する。名前を指定できるなら命名規則を適用する。
3. Gitで直接管理する場合は、リポジトリや環境で定めた保存先を使う。指定がなければリポジトリ外の専用worktree用ディレクトリを選び、編集前に絶対パスを伝える。開始点はユーザー指定を優先し、未指定なら現在のHEADを使う。`git worktree add -b <ブランチ名> <絶対パス> <開始点>` で作成する。未コミット変更は元のworktreeに残る。
4. エージェントの作業場所を新しい絶対パスへ切り替え、そこで `git rev-parse --show-toplevel` と `git status -sb` を確認する。シェルの `cd` が次のツール呼び出しにも保持されるとは限らない。永続的に切り替えられない環境では、以後の呼び出しに作業ディレクトリを明示する。

## 内容が固まったら改名

まず、短い機能名を決め、現在の絶対パス・ブランチ・HEAD・未コミット変更を記録する。すでに適切な名前なら変更不要。

### ブランチ名

IDEのブランチ欄はディレクトリ名と別で、detached HEADではコミット番号が表示される。作業用worktreeでは、フォルダを移動できなくてもブランチを命名する。

- detached HEADなら、名前の衝突を確認して現在のHEADから `git switch -c <ブランチ名>` で作業ブランチを作る。
- 既存のタスク用ブランチが仮名、または作成者などの接頭辞付きなら `git branch -m <新ブランチ名>` で命名規則に合わせて改名する。`main` など共有ブランチやユーザー指定名は保持する。
- 特定コミットの閲覧・検証だけの依頼、またはdetached HEADを維持する明示指示がある場合は状態を保持する。
- 命名前後でHEADと未コミット変更が同じことを確認する。

### アプリやホストが管理するworktree

- 公開されている改名・移動機能があれば使い、タスクと作業パスの対応も更新する。
- ディレクトリ移動後の管理情報とセッションの更新方法を確認できる場合だけ、Gitによる移動を使う。単なる `cd` はホスト側の登録更新にはならない。
- 更新手段がない場合は管理ディレクトリを保持し、変更可能なブランチ名やタスク表示名に短い機能名を反映する。ディレクトリ名が未変更であることと、その理由を報告する。表示名の変更をディレクトリ改名の完了として扱わない。

### Gitで直接管理するworktree

1. 対象がメインの作業ツリーではなく追加worktreeであることと、移動先へのアクセス・移動後の作業場所の指定方法を確認する。
2. 移動で消えない作業ディレクトリから `git -C <同じリポジトリのメイン作業ツリーの絶対パス> worktree move <旧絶対パス> <新絶対パス>` を実行する。通常のファイル移動ではなくGitの操作で登録情報も更新する。
3. 成功したら以後のツール呼び出しを新しい絶対パスへ切り替える。ブランチ名は上記の「ブランチ名」に従って揃える。
4. 一部だけ成功した場合は、実際に存在するパスを使って状態を再確認し、未完了の操作だけ処理する。Gitが移動を拒否した場合は理由を確認し、強制移動や作り直しで回避しない。

## 完了確認

作業ブランチの命名・改名時は、現在の会話タイトル（タスク名・セッション名）もブランチ名に揃える。`codex/` などの環境固有の接頭辞がある場合は除く。Codexでは `set_thread_title` を使い、他の環境では利用可能な会話名変更機能を使う。変更機能がない場合は、会話タイトルの変更を省略し、その旨を報告する。変更した場合は、返されたタイトルまたは画面表示が意図した名前と一致することを確認する。

`git worktree list --porcelain`、対象での `git rev-parse --show-toplevel` と `git status -sb` により、登録パス・ブランチが意図した状態で、HEAD・未コミット変更が保持されていることを確認する。ホスト管理の場合はタスクの参照先も確認する。最終的な絶対パスとブランチ名、未完了の改名があればその理由を報告する。
